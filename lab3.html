Workflow Bypass

Explore how skipping checkout steps can create an unpaid or underpaid order.

OWASP A04:2021 CWE-841 Medium
1. What it is

What is Workflow Bypass?

Workflow bypass happens when an application lets requests skip or change required business steps. In this checkout, an attacker can confirm without paying or change the cart after payment. This is CWE-841 and relates to OWASP A04:2021 Insecure Design.

2. The line

The vulnerable code

app.post("/confirm", async (req, res) => {
  const order = await findOrder(req.session.orderId);
  if (!order) return res.sendStatus(404);
  await createOrder(order); // no payment or state check
  res.send("Order confirmed");
});
Why is this line dangerous?

The server confirms the order without verifying that the correct amount was paid for the current cart.

4. Why it matters

Why does it matter?

Skipping payment can produce free orders; changing a cart after payment can produce orders worth more than the amount paid. Similar missing checks can bypass approvals or other business rules.

5. The fix

The fixed code

app.post("/confirm", async (req, res) => {
  const order = await findOrder(req.session.orderId);
  if (!order) return res.sendStatus(404);
  if (order.state !== "paid" || order.paid !== order.total)
    return res.sendStatus(403);
  await createOrder(order);
  res.send("Order confirmed");
});
Why does the fix work?

The server validates the order state and amount before confirmation. It must also lock the cart once payment starts and enforce valid transitions on every endpoint.
