Predictable Reset Tokens

See how a password-reset token built from public information can be guessed, then compare it with a secure reset flow.

OWASP A07:2025 CWE-640 CWE-340 Challenge
1. What it is

When a reset token is predictable

A reset token is a temporary secret that proves a password-reset request is authorized. If an application builds it from guessable data such as a user ID and date, someone who knows that pattern may be able to create a valid reset link and take over the account.

Safe simulation: This lab uses made-up accounts and tokens in your browser. It does not send email, contact a server, or change a real password.
2. The line

The predictable code

The vulnerable example derives the token from values that are already known or easy to discover.

function createResetToken(user, day) {
  // The account ID and date are not secret.
  const token = user.id + "-" + day;
  saveResetToken(user.id, token);
  sendResetLink(user.email, token);
  return token;
}
Why is this line dangerous? Anyone who can infer the account ID and reset date can reproduce the same value. A reset link should depend on an unpredictable secret, not public account details.

4. Why it matters

Why does it matter?

A valid reset link can let its holder choose a new password without knowing the old one. If the token is predictable, an attacker may use the recovery flow to gain control of another account.

The risk comes from treating a recoverable account link as a secret while generating it from information that is not secret.
5. The fix

Generate a strong, short-lived token

Use a cryptographically secure random generator. Store a hash of the token, bind it to the correct account, expire it, and invalidate it after one successful use.

function createResetToken(user) {
  const token = randomBytes(32).toString("base64url");
  storeHash(user.id, sha256(token), {
    expiresIn: "15 minutes",
    singleUse: true
  });
  sendResetLink(user.email, token);
}
Why does the fix work? The token no longer comes from a guessable formula. Expiration and single-use validation also limit how long a leaked or reused link can work.
